# MES 升级发布窗口执行流程

- 题目编号：`int-o2`
- 所属模块：运维实操营 · MES/ERP/WMS 集成排障
- 题目类型：运维实操（流程排序）
- 难度 / 建议时长：进阶 / 8 分钟
- 文档路径：`public/content/labs/int-o2.md`（站内地址 `/content/labs/int-o2.md`）

## 1. 题目目标与业务背景

**目标**：把MES 升级发布窗口执行流程的标准流程顺序记牢，能在真实变更里按序执行。

**背景**：MES 从 v3.2 升级到 v3.5，涉及数据库结构变更和两个接口调整，计划周日 8 小时窗口执行。排出规范的发布流程顺序。

## 2. 涉及的数据表或服务

- 本题为概念/流程类题目，不直接操作具体服务；演练环境规格见第 4 节。

## 3. 需要的账号与权限

- 需要 sudo 权限（或等价的管理员权限），可读写演练目录、日志目录与服务配置。
- SSH 私钥 / 口令只保存在本站服务端，不进仓库、不进文档。

## 4. 环境要求（演练专用）

### 4.1 规格基线

- 演练服务器最低配置：2 vCPU / 2 GB 内存 / 20 GB 可用磁盘（其中日志分区 ≥ 2 GB）；Debian 12 或 Ubuntu 22.04 及以上，需 systemd
- 演练服务器推荐配置：4 vCPU / 4–8 GB 内存 / 40 GB 可用磁盘（日志分区 ≥ 10 GB）；Debian 13 或 Ubuntu 24.04，Docker 29 可用
- 系统版本：Debian GNU/Linux 12/13 或 Ubuntu 22.04/24.04（systemd + bash + coreutils）

> 规格出处：以下数值对齐已验证过的目标机 instabox dev 实测规格（4 vCPU / 7.8 GiB 内存、根分区 16 GB + 数据盘 20 GB、Debian GNU/Linux 13，内核 6.18，Docker 29.8 可用），最低配置按其一半左右给出，保证题目脚本与路径在演练机上跑得通。

## 5. 标准步骤

1. 发布申请与变更评审：升级内容、影响系统清单、接口变更说明、回退标准（什么情况下必须回退）经三方确认
2. 全量备份：数据库全备+日志备份、应用程序包、配置文件三样齐备并逐个验证可读
3. 预演环境全流程彩排：在与生产同构的测试环境完整走一遍升级+接口回归+回退，记录每步耗时
4. 通知与停写：提前通知车间与对接方，窗口开始时停止采集入口与接口服务，确认无在途事务
5. 按序执行升级：数据库结构变更 → 应用部署 → 配置核对 → 接口服务更新，每步完成后核对版本号与日志
6. 冒烟测试：核心业务逐项试单——登录、报工、工单查询、接口传 ERP、入库传 WMS，对照回归清单打勾
7. 放开使用并进入观察期：通知车间恢复生产，48 小时重点监控错误日志、接口成功率、数据库性能
8. 发布关闭：输出发布报告（时间线/变更项/验证结果/遗留问题），备份与旧版本包保留至观察期结束
