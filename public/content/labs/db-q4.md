## 1. 题目目标与业务背景

**目标**：按班次汇总合格总数与报废总数，输出 shift、ok、scrap 三列，按 shift 升序。

**业务背景**：车间主任想知道白班和夜班的产出差距，好排下个班的排产。work_reports 里 shift 字段只有「白班」「夜班」两种值，合格数与报废数分列。

## 2. 涉及的数据表或服务

- 涉及表：`work_reports`
- 练习库结构：内置练习库共 8 张表（items / bom / employees / equipment / work_orders / work_reports / inventory / sales_orders），合计约 231 行；真实连库时按第 4 节的空间与数据量建议预置同量级数据。

## 3. 需要的账号与权限

- 连接信息只保存在本站服务端（页面与仓库都不落明文密码），列表回显一律脱敏。

## 5. 标准步骤

```sql
SELECT shift, SUM(qty_ok) AS ok, SUM(qty_scrap) AS scrap FROM work_reports GROUP BY shift ORDER BY shift
```

- 思路提示：GROUP BY shift 之后 SUM 聚合，ORDER BY shift 保证输出顺序稳定
- 讲解：最简单的分组聚合，但注意「输出顺序」这个细节：不加 ORDER BY 时数据库不保证行序，两次查询结果顺序可能不同——对报表和自动校验都是隐患。养成 GROUP BY 必带 ORDER BY 的习惯，这是职业化 SQL 和随手 SQL 的区别。

## 6. 验收标准（可机器判定）

判分方式：执行下面的校验 SQL，结果必须与期望值完全一致（列名与行序都算）。

```sql
SELECT shift, SUM(qty_ok) AS ok, SUM(qty_scrap) AS scrap FROM work_reports GROUP BY shift ORDER BY shift
```

- 期望结果：`[["夜班",257,32],["白班",676,56]]`

## 7. 常见错误与排查提示

- 常见错法：GROUP BY shift 之后 SUM 聚合，ORDER BY shift 保证输出顺序稳定
- 为什么：最简单的分组聚合，但注意「输出顺序」这个细节：不加 ORDER BY 时数据库不保证行序，两次查询结果顺序可能不同——对报表和自动校验都是隐患。养成 GROUP BY 必带 ORDER BY 的习惯，这是职业化 SQL 和随手 SQL 的区别。

## 8. AI 环境准备步骤（供站内 AI 生成准备脚本）

AI 应当按下面的顺序在**用户填写的演练环境**上生成准备脚本；每条命令都必须先预览、由用户确认后再执行，命中站内危险命令清单的一律二次确认。

- 确认连接可达：先跑一条只读查询（如 `SELECT 1`）确认账号、库名、网络都通。
- 确认目标表存在且结构一致：跑 `SHOW COLUMNS` / `\d` 之类只读命令核对字段名与类型。
