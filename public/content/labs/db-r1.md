## 1. 题目目标与业务背景

**目标**：按日期汇总合格总数与报废总数，输出 d（日期，格式 2026-10-05）、ok、scrap 三列，按 d 升序取前 10 天。

**业务背景**：每天早上 8 点，生产经理要在群里看到昨天的日报：每天合格多少、报废多少。report_time 是「2026-10-05 14:30:00」格式的时间戳，按天汇总要先把它截成日期。

## 2. 涉及的数据表或服务

- 涉及表：`work_reports`
- 练习库结构：内置练习库共 8 张表（items / bom / employees / equipment / work_orders / work_reports / inventory / sales_orders），合计约 231 行；真实连库时按第 4 节的空间与数据量建议预置同量级数据。

## 5. 标准步骤

```sql
SELECT SUBSTR(report_time, 1, 10) AS d, SUM(qty_ok) AS ok, SUM(qty_scrap) AS scrap FROM work_reports GROUP BY d ORDER BY d LIMIT 10
```

- 思路提示：SUBSTR(report_time, 1, 10) 从时间戳里截出日期部分，再按它 GROUP BY
- 讲解：按时间维度汇总是报表第一大类。日期截取函数各库不同：SQLite 用 SUBSTR、MySQL 用 DATE()、SQL Server 用 CAST(x AS date)、PostgreSQL 用 x::date 或 DATE_TRUNC——给不同客户写日报时要会切换。进阶一步：跨零点的夜班报工该算哪天的产量？按报工时间还是按班次归属日？这种口径问题先跟生产经理对齐再写 SQL，不然报表发出去就吵。

## 6. 验收标准（可机器判定）

判分方式：执行下面的校验 SQL，结果必须与期望值完全一致（列名与行序都算）。

```sql
SELECT SUBSTR(report_time, 1, 10) AS d, SUM(qty_ok) AS ok, SUM(qty_scrap) AS scrap FROM work_reports GROUP BY d ORDER BY d LIMIT 10
```

- 期望结果：`[["2026-10-01",17,7],["2026-10-02",20,0],["2026-10-03",48,3],["2026-10-04",48,2],["2026-10-05",25,4],["2026-10-06",63,14],["2026-10-07",44,2],["2026-10-08",34,0],["2026-10-09",29,3],["2026-10-10",52,0]]`

## 7. 常见错误与排查提示

- 常见错法：SUBSTR(report_time, 1, 10) 从时间戳里截出日期部分，再按它 GROUP BY
- 为什么：按时间维度汇总是报表第一大类。日期截取函数各库不同：SQLite 用 SUBSTR、MySQL 用 DATE()、SQL Server 用 CAST(x AS date)、PostgreSQL 用 x::date 或 DATE_TRUNC——给不同客户写日报时要会切换。进阶一步：跨零点的夜班报工该算哪天的产量？按报工时间还是按班次归属日？这种口径问题先跟生产经理对齐再写 SQL，不然报表发出去就吵。
