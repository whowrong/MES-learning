# 迁云后 MES 访问不通：双层网络排查

## 1. 题目目标与业务背景

**目标**：由内向外逐层排查网络路径，放行必要端口，并且只放行必要来源——不能把 MES 裸奔在公网。

**背景**：机械厂把 MES 迁到云主机（公网 EIP 47.98.x.x，内网 172.16.0.11），车间通过公司固定出口 IP 203.0.113.26 访问。你已 SSH 登录云主机。

**现象**：迁移完成当晚，车间与办公室全都打不开 MES 页面（http://47.98.x.x:8080），浏览器一直转圈到超时。

## 2. 涉及的数据表或服务

- MES 应用（主机内监听 8080）
- firewalld（主机防火墙）
- 云安全组（云 CLI 管理入方向规则）

## 3. 需要的账号与权限

- 需要 sudo 权限改主机防火墙；云账号需要安全组只读查看 + 入方向规则增改权限
- SSH 私钥 / 口令只保存在本站服务端，不进仓库、不进文档。

## 4. 环境要求（演练专用）

### 4.1 规格基线

- 演练服务器最低配置：2 vCPU / 2 GB 内存 / 20 GB 可用磁盘（其中日志分区 ≥ 2 GB）；Debian 12 或 Ubuntu 22.04 及以上，需 systemd

- 系统版本：Debian GNU/Linux 12/13 或 Ubuntu 22.04/24.04（systemd + bash + coreutils）

> 规格出处：以下数值对齐已验证过的目标机 instabox dev 实测规格（4 vCPU / 7.8 GiB 内存、根分区 16 GB + 数据盘 20 GB、Debian GNU/Linux 13，内核 6.18，Docker 29.8 可用），最低配置按其一半左右给出，保证题目脚本与路径在演练机上跑得通。

### 4.2 额外要求

## 7. 常见错误与排查提示

- 确认 MES 应用在主机内正常监听 8080：ss -lntp | grep 8080，先确认应用自己在监听，且监听的是 0.0.0.0 而不是 127.0.0.1。
- 要点：应用在，且监听 0.0.0.0（所有网卡）——如果监听的是 127.0.0.1，外部永远进不来，这是迁云后最常见的应用侧配置坑。本次应用侧正常，问题在链路上。
- 本机自测应用响应，把应用层嫌疑彻底排除：curl -sI http://127.0.0.1:8080 本机探活。
- 要点：本机 200，应用层无罪。排查范围收敛到网络路径：主机防火墙 → 云平台安全组 → 公网链路，由内向外一层层过。
- 检查主机防火墙（firewalld）是否放行 8080：firewall-cmd --list-all 看 public 区放行了哪些端口。
- 要点：只放行了 22（SSH），没有 8080——第一道墙就堵着。迁移脚本只搬了应用，没人管新环境的防火墙基线，这是迁云漏项重灾区。
- 放行主机防火墙 8080 并永久生效：firewall-cmd --add-port=8080/tcp --permanent 写入永久配置，再 firewall-cmd --reload 生效。
- 要点：不带 --permanent 的规则重启即失，带了不 --reload 不生效——两个都要。放完主机防火墙还不通？因为云主机还有第二道墙：安全组，它在主机外面、云平台那一层。
- 用云 CLI 查看本机所绑安全组的入方向规则：演练环境模拟云 CLI：aliyun ecs DescribeSecurityGroupAttribute --SecurityGroupId <id> --Direction ingress。
- 要点：确认第二道墙也堵着，而且顺带看到 3389 对全网开放的历史遗留——那台是 Linux 根本用不上 RDP，这条规则该清理。安全组是云上第一道也是最容易被忽略的关卡。
- 添加安全组规则：8080 只对工厂固定出口 IP 放行：aliyun ecs AuthorizeSecurityGroup，参数：--PortRange 8080/8080 --SourceCidrIp 203.0.113.26/32。切记来源写工厂出口 IP，不是 0.0.0.0/0。
- 要点：最小开放原则：MES 是内部生产系统，登录页挂到全网等于给扫描器和撞库开门。来源收紧到工厂固定出口 /32，办公室如有固定出口再单独加一条，每条规则写清 Description。
- 端到端验证：从工厂网络侧访问公网地址确认打通：让工厂网络侧 curl 或浏览器访问 http://公网IP:8080，验证要站在用户的网络位置做。
- 要点：在主机上自己 curl 公网 IP 说明不了问题（流量路径不同），必须从真实访问来源验证。收尾动作：清理 3389 遗留规则、把安全组与防火墙配置写进迁移交付清单。
- 把 8080 对 0.0.0.0/0 放行：题目要求只对固定出口 IP 放行，站内危险命令清单会拦截
- 只放行主机防火墙忘了安全组：两层都要通

AI 应当按下面的顺序在**用户填写的演练环境**上生成准备脚本；每条命令都必须先预览、由用户确认后再执行，命中站内危险命令清单的一律二次确认。

## 9. AI 执行脚本要点（供站内 AI 生成执行脚本）

- 先确认应用在主机内监听 8080 并本机自测响应，把应用层嫌疑排除
- 检查 firewalld 是否放行 8080，放行并永久生效（--permanent + reload）
- 用云 CLI 查看本机绑定的安全组入方向规则，添加 8080 且只对固定出口 IP 放行
- 从「工厂网络侧」发起访问验证端到端打通
- 验收正则覆盖：监听确认 / 本机自测 / firewalld / 安全组查询 / 安全组放行 / 端到端验证
