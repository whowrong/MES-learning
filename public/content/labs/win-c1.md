## 1. 题目目标与业务背景

**目标**：掌握Windows 运维高频场景八题相关的场景判断与处置原则。

**背景**：小厂 Windows 服务器上 MES/ERP 运维的八个高频真实场景：共享访问、计划任务、服务报错、远程桌面、防火墙、补丁管理、备份路径、远程失联。

- 本题为概念/流程类题目，不直接操作具体服务；演练环境规格见第 4 节。

## 3. 需要的账号与权限

- 需要 sudo 权限（或等价的管理员权限），可读写演练目录、日志目录与服务配置。
- SSH 私钥 / 口令只保存在本站服务端，不进仓库、不进文档。

## 4. 环境要求（演练专用）

### 4.1 规格基线

- 演练服务器最低配置：2 vCPU / 2 GB 内存 / 20 GB 可用磁盘（其中日志分区 ≥ 2 GB）；Debian 12 或 Ubuntu 22.04 及以上，需 systemd
- 演练服务器推荐配置：4 vCPU / 4–8 GB 内存 / 40 GB 可用磁盘（日志分区 ≥ 10 GB）；Debian 13 或 Ubuntu 24.04，Docker 29 可用
- 系统版本：Debian GNU/Linux 12/13 或 Ubuntu 22.04/24.04（systemd + bash + coreutils）

> 规格出处：以下数值对齐已验证过的目标机 instabox dev 实测规格（4 vCPU / 7.8 GiB 内存、根分区 16 GB + 数据盘 20 GB、Debian GNU/Linux 13，内核 6.18，Docker 29.8 可用），最低配置按其一半左右给出，保证题目脚本与路径在演练机上跑得通。

### 4.2 额外要求

- 无额外要求：按题目用到的服务预置即可。

## 5. 标准步骤

- 车间一台 Win10 终端突然打不开 MES 服务器的共享目录（\\192.168.1.10\mesfiles），报「找不到网络路径」，其它终端正常。第一步排查方向是？
- MES 服务器上每天凌晨 1 点的自动备份计划任务连续三天没跑，任务计划程序里显示「上次运行结果 0x1」。最可能的原因是？
- MES 的 Windows 服务启动失败，服务弹窗只给一个错误码 1067「进程意外终止」。去哪里能看到它到底为什么死？
- 实施同事把 MES 数据采集程序直接双击跑在服务器的桌面上，用他的远程桌面窗口挂着。他下班断开远程后，采集就停了。规范的做法是？

- 周三下午 Windows 自动更新触发重启，正在运行的 MES 服务被硬停，车间报工中断 20 分钟。长效机制是？
- SQL Server 备份作业直接写到网络路径 \\nas01\sqlbak，最近频繁报「找不到网络路径」，但 NAS 本身正常。最稳妥的整改是？
- 一台 Windows Server（MES 数据库服务器）突然远程桌面连不上，ping 也不通，但机房指示灯正常。第一步应该？
