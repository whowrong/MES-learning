## 1. 题目目标与业务背景

**目标**：查出 due_date 早于 2026-11-01 的订单，输出 order_no、due_date、qty（订单量）、done（对应工单完工数合计，没有工单记 0）四列，按 due_date 升序取前 10。

**业务背景**：销售内勤每周一要一张交期预警表：11 月之前到期的订单，对应的生产工单做到什么程度了。订单在 sales_orders，生产进度在 work_orders，两边靠物料编码关联——一个成品可能有多张工单，进度要加总。

## 2. 涉及的数据表或服务

- 涉及表：`sales_orders`、`work_orders`
- 练习库结构：内置练习库共 8 张表（items / bom / employees / equipment / work_orders / work_reports / inventory / sales_orders），合计约 231 行；真实连库时按第 4 节的空间与数据量建议预置同量级数据。

## 5. 标准步骤

```sql
SELECT s.order_no, s.due_date, s.qty, COALESCE(SUM(w.done_qty), 0) AS done FROM sales_orders s LEFT JOIN work_orders w ON w.item_code = s.item_code WHERE s.due_date < '2026-11-01' GROUP BY s.order_no ORDER BY s.due_date, s.order_no LIMIT 10
```

- 思路提示：LEFT JOIN + COALESCE(SUM(...), 0)：没排产的订单 done 显示 0 而不是消失；日期字符串 '2026-11-01' 可以直接比较大小
- 讲解：这题综合了预警报表的全部要点：LEFT JOIN 保住「还没排产」的最危险订单（内连接会让它们凭空消失）、COALESCE 把 NULL 归零、字符串日期直接比较（ISO 格式的日期字符串字典序=时间序，这是日期存成 YYYY-MM-DD 的最大红利）。真实项目里订单和工单之间还隔着计划层（一单多批、拼单生产），关联键要用订单行号而不是物料编码——用物料编码关联在「同物料多订单」时会互相污染，这是新手顾问最常踩的报表坑。

## 6. 验收标准（可机器判定）

判分方式：执行下面的校验 SQL，结果必须与期望值完全一致（列名与行序都算）。

```sql
SELECT s.order_no, s.due_date, s.qty, COALESCE(SUM(w.done_qty), 0) AS done FROM sales_orders s LEFT JOIN work_orders w ON w.item_code = s.item_code WHERE s.due_date < '2026-11-01' GROUP BY s.order_no ORDER BY s.due_date, s.order_no LIMIT 10
```

- 期望结果：`[["SO2026215","2026-10-04",7,359],["SO2026214","2026-10-18",8,359],["SO2026201","2026-10-22",37,121],["SO2026208","2026-10-24",26,121]]`

## 7. 常见错误与排查提示

- 常见错法：LEFT JOIN + COALESCE(SUM(...), 0)：没排产的订单 done 显示 0 而不是消失；日期字符串 '2026-11-01' 可以直接比较大小
- 为什么：这题综合了预警报表的全部要点：LEFT JOIN 保住「还没排产」的最危险订单（内连接会让它们凭空消失）、COALESCE 把 NULL 归零、字符串日期直接比较（ISO 格式的日期字符串字典序=时间序，这是日期存成 YYYY-MM-DD 的最大红利）。真实项目里订单和工单之间还隔着计划层（一单多批、拼单生产），关联键要用订单行号而不是物料编码——用物料编码关联在「同物料多订单」时会互相污染，这是新手顾问最常踩的报表坑。
