## 1. 题目目标与业务背景

**目标**：统计所有「已完工」的工单数量（Completed、已完成、完成 三种写法都算完工），输出一列 n。

**业务背景**：项目月会上客户老板问：「10 月你们系统里到底完工了多少张工单？」你打开 work_orders 表发现 status 字段里同时存在 Completed、已完成、完成 三种写法——上线初期录入没管住，这是实施现场最常见的口径陷阱。

## 2. 涉及的数据表或服务

- 涉及表：`work_orders`
- 练习库结构：内置练习库共 8 张表（items / bom / employees / equipment / work_orders / work_reports / inventory / sales_orders），合计约 231 行；真实连库时按第 4 节的空间与数据量建议预置同量级数据。

## 3. 需要的账号与权限

- 只需要 SELECT 权限（只读账号即可作答）。
- 连接信息只保存在本站服务端（页面与仓库都不落明文密码），列表回显一律脱敏。

## 5. 标准步骤

```sql
SELECT COUNT(*) AS n FROM work_orders WHERE status IN ('Completed','已完成','完成')
```

- 思路提示：status 的取值不止一种写法，IN (...) 把三种都列进去
- 讲解：COUNT(*) + WHERE status IN (...) 是口径归类的标准写法。实施现场的教训：上线前必须把状态字典管住（枚举值 + 录入约束），否则每个报表都要写这种「翻译」条件，漏一种写法数就错。汇报口径时记得注明「含历史多种写法」，让客户知道数据治理欠账在哪。

## 6. 验收标准（可机器判定）

判分方式：执行下面的校验 SQL，结果必须与期望值完全一致（列名与行序都算）。

```sql
SELECT COUNT(*) AS n FROM work_orders WHERE status IN ('Completed','已完成','完成')
```

- 期望结果：`[[16]]`

## 7. 常见错误与排查提示

- 常见错法：status 的取值不止一种写法，IN (...) 把三种都列进去
- 为什么：COUNT(*) + WHERE status IN (...) 是口径归类的标准写法。实施现场的教训：上线前必须把状态字典管住（枚举值 + 录入约束），否则每个报表都要写这种「翻译」条件，漏一种写法数就错。汇报口径时记得注明「含历史多种写法」，让客户知道数据治理欠账在哪。

## 8. AI 环境准备步骤（供站内 AI 生成准备脚本）

AI 应当按下面的顺序在**用户填写的演练环境**上生成准备脚本；每条命令都必须先预览、由用户确认后再执行，命中站内危险命令清单的一律二次确认。

- 确认连接可达：先跑一条只读查询（如 `SELECT 1`）确认账号、库名、网络都通。
- 确认目标表存在且结构一致：跑 `SHOW COLUMNS` / `\d` 之类只读命令核对字段名与类型。
- 预置脏数据：按本题的场景补齐需要的脏数据行（脏值、多写法状态值、尾部空格等），并记录补了多少行以便回滚。
- 记录基线：把关键表的行数与关键汇总值（本题校验 SQL 的期望值）先查一遍存下来，作为回滚与验收基准。

## 9. AI 执行脚本要点（供站内 AI 生成执行脚本）

- 先跑只读校验：`SELECT COUNT(*) AS n FROM work_orders WHERE status IN ('Completed','已完成','完成')`
- 再跑用户的作答 SQL，并把结果与校验 SQL 的期望值比对；不一致要指出差在哪一行、差多少。
- 涉及写操作（UPDATE/DELETE）时，先用 SELECT 预览受影响的行数，确认行数与预期一致再提交。
